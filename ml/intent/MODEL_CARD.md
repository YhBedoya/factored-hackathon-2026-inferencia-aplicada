# Model card: intent_clf@v4

Intent classifier for the LLM-free degraded mode of Cardy (Swip card support). Report: [`runs/compare_s42/nlu_classifier.md`](runs/compare_s42/nlu_classifier.md).

## Intended use

NLU of the degraded mode only (ADR-032): when the LLM provider is unavailable, the classifier turns a masked customer message into intents so the flows can still ask, clarify or resolve read-only cases. It is never the primary path. Below the threshold τ it returns `ambiguous` and the bot asks. By policy (`policies/escalation.yaml` v6, `degraded_handoff_intents`) degraded mode hands off `transaction_search`, `general_question` and `decline_explain` instead of answering: they have no safe keyword answer.

Out of scope: serving `transaction_search`, `general_question` and `decline_explain` in degraded mode (they hand off), the primary NLU path, any use on text that is not PII-masked, languages other than es-MX, es-CO, es-AR and pt-BR, intents outside the 22 labels (loans, insurance and other topics land on out-of-scope classes or `ambiguous`), and any decision that executes a side effect without the confirmation-token flow.

## Data

- `intent-data@v1`, label set `v1`: 22 classes x 4 locales. 2,902 accepted items, 838 rejected (kept in the files with `accepted: false`).
- Every item is AI-generated by gpt-6-luna (prompts `intent_gen@v1`, `v2`, `v3` in `ml/intent/prompts/`). Provenance header: `ai-generated-human-audited`. No real customer text.
- Items come in families (a seed plus paraphrases). Seed 33%, paraphrase 67%.
- Slots: plain, regional, typo_informal, hard_negative, negation, short_answer, card_type. The `card_type` slot (credit or debit named in the text) excludes greeting, thanks_close, affirm and deny.
- PII appears only as the runtime placeholder `⟨KIND_n⟩` (`app.core.pii.TOKEN_RE`).
- Leakage check against dev: 0 matches.

## Model

Selected by rule D17 (smallest served bundle within the 95% CI of the best grouped 5-fold CV macro-F1, folds grouped by family): C2, TF-IDF `char_wb` n-grams 2 to 5 + logistic regression, C = 100, `max_iter` 2000. Best CV was C2 at 0.941, CI [0.924, 0.958]; inside the CI were C2 and C3A (e5-small + LR). C2 size: 3.5 MB uncompressed (the fitted head); the served tarball is 2,239,717 bytes (2.2 MB). p95 CPU latency 3 ms. Seed 42. Dev scores were not used to choose.

## Threshold

τ = 0.35, chosen on out-of-fold predictions (D18). Cost rule: wrong side-effect intent = 5, wrong read-only intent = 2, clarification = 1. Side-effect intents are `card_block`, `card_unlock`, `replacement_request`, `unrecognized_charge`. Ties go to the higher τ.

| τ | Coverage | Wrong side-effect | Wrong read-only | Clarifications | Total cost |
|---|---|---|---|---|---|
| 0.20 | 99.7% | 45 | 113 | 9 | 460 |
| **0.35** | 97.3% | 40 | 90 | 77 | **457** |
| 0.50 | 93.6% | 32 | 67 | 186 | 480 |

The cost gap between the three rows is small (457 against 460 and 480).

## Metrics

Dev set: 56 seed items. Macro-F1 intervals are 95% bootstrap CIs; exact-set, status accuracy and recall intervals are 95% Wilson intervals. Held-out: not run.

| System | Macro-F1 | Exact-set match |
|---|---|---|
| C1 keyword rules | 0.52 [0.39, 0.62] | 55.4% [42.4%, 67.6%] |
| **C2 = intent_clf@v4** | 0.67 [0.51, 0.75] | 64.3% [51.2%, 75.5%] |
| Ref (Claude reference) | 0.86 [0.73, 0.91] | 82.1% [70.2%, 90.0%] |

Grouped-CV macro-F1 of C2: 0.941 ± 0.014. C2 status accuracy 85.0%, out-of-scope recall 2/2, false abstain 0/18. Paired test on exact-set against the keyword baseline: C2 +8/-3, McNemar p = 0.227; Ref +18/-3, p = 0.001. Per locale, C2 exact-set: es-AR 3/6, es-CO 5/7, es-MX 6/7, pt-BR 4/12, mixed 3/4.

End to end (report section 7): with the classifier loaded, 8 degraded scenarios give 1 resolved, 4 clarified, 3 handed off (the `decline_explain` variants, by policy), 0 abstained, 0 unsafe; 4 verdicts passed, 4 failed (the 3 handoffs against a normal-mode `resolved` label, and `card_status`, which clarifies because the persona has two cards). With the classifier not loaded, 8 of 8 hand off. An earlier run counted `decline_explain` as resolved with a canned apology, before this policy.

## Limitations

1. All training data is AI-generated by gpt-6-luna (`intent_gen@v1`, `v2`, `v3`).
2. Human audit: the human read every v1 item. The 792 v2 items and the 263 `card_type` (v3) items were accepted without a human read, and 44 replacement items were accepted from a list.
3. 11 phrases repeat across files with the same label (check WARNs), so cross-validation is slightly optimistic. One cell has 29 base items; the check passes cells with 29 or more.
4. CV macro-F1 is 0.94 but dev macro-F1 is 0.67 [0.51, 0.75] on 56 seeds: synthetic register does not transfer fully.
5. pt-BR is the weakest locale (C2 4/12 exact-set; Ref 7/12).
6. On the 56 dev items C2 is not significantly better than the keyword baseline (McNemar +8/-3, p 0.227); the Claude reference is (+18/-3, p 0.001). C2 was selected by rule D17 on CV, not because it beat the baseline on dev.
7. No held-out run was made.
8. A full offline app start was not proven; only that the classifier loads from the bundle.
9. The bundle-cleanup failure path is covered by code position only, not by a test.
10. C3a's low exact-set rate (26.8%) despite macro-F1 0.68 is not explained.
11. The Ref cost column ($0.0162) is the mean over the 54 paid calls (2 of 56 were refused), so it is per call, not per run. A run costs about $0.87 (0.016183 x 54).
12. scikit-learn is pinned `>=1.6` (locked 1.9.1), with no load-time version check against the bundle manifest. Decided: the loader refuses any bundle that fails to unpickle and the app then hands off. Silent behaviour drift across library versions is not detected.
13. The bundle manifest records no library versions (keys: candidate, data_sha256, data_version, embedding_model, hyperparameters, label_set_version, labels, model_id, seed, tau).
14. No training item contains a runtime mask token (`⟨KIND_n⟩`), while served text is masked and can contain them. Behaviour on masked tokens is untested.
15. S3 storage is deferred to deploy. The bundle lives in `ml/intent/models/` (git-ignored), pinned by sha256 in `ml/intent/model.lock`.

## Retrain and pin

```bash
make intent-train SEED=42     # trains all candidates, grouped CV, out-of-fold predictions
make intent-compare SEED=42   # report run, winner, τ, bundle, model.lock
```

`intent-compare` exports the bundle `ml/intent/models/intent_clf@v<N>.tar.gz`, writes its version and sha256 to `ml/intent/model.lock`, and removes older bundles. Each export bumps the version. The backend loads the bundle named in `model.lock` and refuses it if the sha256 does not match. Current pin: `intent_clf@v4`, sha256 `7e5b03af27f01dbe28814ef994e56709e85019b0437665985bf1ac0f0e45f725`.
