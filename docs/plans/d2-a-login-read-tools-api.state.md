## Conventions established for this card
Full list: plan §"Facts checked against the repo". The ones every task needs:
- Run commands as `cd backend && uv run …`. No pytest-asyncio: drive coroutines with `asyncio.run(...)`.
- `get_settings()`, `get_engine()` and `get_redis()` are `lru_cache`d and bound to their event loop, so `cache_clear()` all three when a test switches the DB or the loop.
- Run Alembic as a subprocess with `DATABASE_URL` in its env, never in-process.
- psycopg DSNs drop `+asyncpg` from `DATABASE_URL`.
- import-linter: conversation and core never import `*/repository.py`. Conversation persistence goes in `conversation/store.py`.
- mypy strict applies to `app.core.*` and `app.domains.conversation.*`.
- Login is customer-only (document_type + document_number + password). The document number is never stored, logged or used as a key in plain text; use the HMAC `login_key`.
- Errors are `HTTPException(status, detail="<code>")`. CSRF failure is `403 csrf_failed`. A failed turn emits SSE `error{"code":"turn_failed"}` then `done`.
- No Redis prefix: tests use a per-run `IDENTITY_HMAC_KEY` and fresh UUIDs, and delete their own keys.
- Integration Verify fails on a skip: pipe pytest through `tail -1 | grep -E '^[0-9]+ passed(, [0-9]+ warnings?)? in'`.
- `customers.service.LoginProfile.document_type` is a plain `str` (customers doesn't import identity); identity code converts it to `DocumentType` where needed (T4).
- Tests always use a fake LLM (`ScriptedLLM`), never a real provider.
