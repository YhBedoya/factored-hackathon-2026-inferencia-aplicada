## Settled after the spec gate (binding on every task)

- **Decline alert window = 7 days.** The home raises "recent declined transaction" for the newest `Declined` row on the first `/me/transactions` page whose `occurred_at` is within the last 7 days. The frontend has no `BANK_TZ` table, so it compares against the browser clock (`now - 7 × 24 h`).
- **Salutation boundaries (country local time, `BANK_TZ[country]`):** morning 05:00–11:59, afternoon 12:00–18:59, evening 19:00–04:59.
- **Planner addition, not in the spec's touch map:** `conversation/tools/registry.py` gains `session_profile(ctx) -> CustomerProfile`. It mirrors `known_pii` (unaudited, through `_bank_reads`). Nothing else in `app.domains.conversation` may reach the profile without it (see Facts, import-linter), and D5 requires the registry as the source.

Execution model: tasks in the same wave run at the same time **in one shared checkout** (no worktrees, no branches, no commits; the orchestrator commits). Within a wave no two tasks touch the same file.

## Risks and mitigations

1. **A `/me` route takes `customer_id`, or declares its role only per route (R1, R13).** T1 declares role + CSRF on the `APIRouter`, and its Verify runs `test_r1_routes.py` and `test_r13_routes.py`.
2. **A foreign card leaks through the transactions filter or through a differing error body.** T1 checks ownership with `cards.service.get_card_details` before paging. `AccessDenied` and `NotFound` both map to `404 {"detail":"not_found"}`. `test_r1_me_routes.py` asserts the identical body for foreign and unknown ids, and that B's lists contain none of A's ids.
3. **The debit balance is shown (A1).** The view builder nulls `current_balance`, `credit_limit`, `available_credit` and `days_past_due` for debit, and `test_me_views.py` asserts it.
4. **Paging changes the LLM tool's `search` (Ask-first boundary).** T1 adds a separate query. Its Verify runs the existing `test_r1_postgres_tools.py` to show `search` is unchanged.
5. **A bad cursor or a date window over 366 days becomes a `500`.** T1 catches the cursor decode error and the `TxFilter` `ValidationError` and raises `422`. The acceptance names both cases.
6. **`welcome.py` imports a bank service and breaks `conversation-no-repository`.** T2 reads the profile only through `registry.session_profile` / `known_pii`. T3 runs `uv run lint-imports`.
7. **The welcome name reaches `content_masked` unmasked (R5).** T2 masks with `PostgresPiiVault(conversation_id).mask(text, known_pii)`, the runner's pattern. The ES/PT test asserts the name is absent from `content_masked` (it uses `InMemoryPiiVault` in place of the Postgres one).
8. **A digit slips into a welcome template.** T2's Verify runs a one-liner that fails on any digit in the new templates.
9. **The eval driver changes behaviour.** `welcome` defaults to `false`, so a `{}` body is unchanged. `test_welcome.py` and the eval path never send `welcome` unless they mean to.
10. **`make client` fails again, or regenerates CRLF noise.** T3 restores `frontend/src/client` from git first, deletes the stray log and runs the in-container equivalent against `http://nginx/...`. It checks `git diff --stat frontend/src/client` for real content changes only.
11. **StrictMode's double effect in dev creates two conversations and two welcomes.** T4 keeps an in-flight create promise in a ref, so a second call reuses it.
12. **The welcome shifts existing e2e assertions.** `session-expiry.es.spec.ts:96` expects 0 bot messages. T4 updates it to exactly one bot message (the welcome) and 0 customer messages, and runs all four chat specs. `.last()` assertions elsewhere are unaffected.
13. **A home button executes a write (Never boundary).** T5's quick actions and alerts only open the panel with a `prefill` string. Nothing in `components/home/` imports `postMessage`, `postConfirmation` or `postSelection`, and T5's Verify greps for that.
14. **The frontend formats money or dates (R4/D7).** T5 renders only the `*_display` / `mask` strings from the API. Its Verify greps `components/home` for `Intl.` and `toLocale`.
15. **Parallel builds collide.** Frontend tasks are one per wave, and each builds alone.
16. **The design export is missing when T7 comes up.** T7 starts with `test -f docs/design/landing/SwipLanding-v2.html`. If that fails it stops and reports "R1 moves to a follow-up card" (D11), with no partial landing.
