## Objective

With `AGENT_ENABLED` on, Cardy handles **unlock** and **replacement** herself instead of passing them to the pipeline. She proposes `unlock` and `replace` steps through `propose_plan`; code checks the preconditions from `policies/tools.yaml`, runs the step-up OTP (and, for a new address, a code-only address turn) **before** any plan is issued, then shows one agent plan with "Acepto / No acepto" that `agent_plan` executes with a read-back per step (ADR-027). The OTP is entered in a modal with Send and Cancel while the chat input is disabled (Q5). When someone asks to unlock a permanently blocked card, code makes the same replacement offer `card_unlock` makes today, and every replacement offer made on the agent path (this one and S1's after-block offer) carries `bot_offered`, so a decline is recorded `cancelled` + `bot_offered`. This serves the three S2 "Done when" lines: (1) unlock and replacement in the browser in ES and PT, OTP included; (2) a plan that needs step-up cannot be issued without a valid one (R2 test); (3) a declined replacement offer is `cancelled` and `bot_offered`. It also closes S1's open item F2 for requests Cardy handles: an unlock or replacement she proposes is confirmed by button only. The code-made offer still leads into the pipeline replacement flow, where a typed "sí" confirms (S1 D28, D34, kept by Q1).

Flag off, `flows/card_unlock.py`, `flows/replacement.py`, `allowed_intents` and the degraded path are unchanged (A2).

## Contracts (delta only)

Everything not listed here is as in `04` §1, §3, §5, §7 and the S1 spec's Contracts.

**`policies/tools.yaml` → version 3** (`04` §5). `Preconditions` (`domains/policy/tools_policy.py`): `status_not_in` becomes optional (default `[]`) and gains two optional rules.

```yaml
version: 3
tools:
  cards.unlock_card:       {requires_confirmation: true, step_up: always,               allowed_intents: [card_unlock],         preconditions: {block_origin_in: [customer_lock]}}
  cards.order_replacement: {requires_confirmation: true, step_up: when_address_changed, allowed_intents: [replacement_request], preconditions: {replacement_eligible: true}}
  # lock_card, block_card: unchanged
```

`block_origin_in`: the card's `get_block_origin` result must be in the list, else `not_locked` (origin `none`), `permanent_block` (`customer_block`) or the `bank_side_block` handoff (D6). `replacement_eligible: true`: origin in `card_select.yaml` `replacement.eligible_origins` or card expired, else `not_eligible`. The `customer_not_active` check (D5) applies to every agent write step and reads `escalation.yaml`.

**`propose_plan`** (`agent/plan.py`):

```python
class ProposedStep(BaseModel):
    action: Literal["lock", "block", "unlock", "replace"]
    card: str                                            # a reference from this turn's tool results (S1 D8)
    address: Literal["on_file", "new"] | None = None     # required for "replace", rejected otherwise
_TOOL_BY_ACTION |= {"unlock": "cards.unlock_card", "replace": "cards.order_replacement"}
```

Tool result: `accepted` | `accepted (step_up_required)` | `accepted (address_required)` | `rejected (<card>: <code>, ...)`, codes from S1 plus `not_locked`, `permanent_block`, `not_eligible`, `address_mismatch`. A handoff precondition ends the loop through a control exception (D6).

**Graph state** (`state.py`, checkpointed):

```python
class AgentPlanStep(TypedDict):
    action: Literal["lock", "block", "unlock", "replace"]
    card_id: str
    address_ref: NotRequired[str]   # "on_file" or "⟨ADDR_n⟩"; absent on a "new" replace until the address turn
```

New `pending` values: `{"flow": "agent", "node": "otp", "awaiting_slot": "otp"}` and `{"flow": "agent", "node": "address", "awaiting_slot": "address"}`. Segments at those pauses are `awaiting` with that slot (`04` §6).

**`issue_plan(steps, intent=None)`**: after the S1 preconditions gate, for each step `if step_up_rule(tool, args) and not await is_step_up_valid()`: record `rule_hit {"rule_id": "step_up_required", "tool": tool}`, raise `StepUpRequired`. Unchanged when `intent` is set.

**UI** (`ui.py`, `04` §3): `OtpRequiredPayload(tool: str, cancellable: bool = False)`; `true` only for the agent OTP pause. **Amended (D31):** the default becomes `True`, so every OTP pause sends `true`.

**HTTP** (`api/v1/conversations.py`, `04` §3): `PostMessageRequest.resume: Literal["step_up", "step_up_cancel"] | None`. Gate before scheduling (D15, D17): at the agent OTP pause a `text` body → `409 otp_required`; `step_up_cancel` anywhere else → `409 cancel_invalid`. **Amended (D30):** `step_up_cancel` is accepted at any `awaiting_slot == "otp"` pause (an agent pause only with the flag on).

**OTP exits** (D26–D29, `04` §3, §4, §5):
- `POST /auth/otp/verify` body: `OtpVerifyRequest{code: str, conversation_id: UUID | None = None}` (`extra="forbid"`). New response `429 otp_handoff` (D27). `404 not_found` for a conversation the session's customer does not own.
- `identity_service.verify_otp(session, code, *, max_failures: int, limiter=None, settings=None)`; `LoginLimiter` gains `async reset(key: str) -> None` (Redis `DEL`).
- `TurnInput.resume` / `GraphState.resume` / `runner.start_turn`: `Literal["step_up", "step_up_cancel", "step_up_failed"] | None`; `step_up_failed` is started only by the verify route.
