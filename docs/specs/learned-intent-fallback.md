# Spec: REQ-learned-intent-fallback — learned intent classifier and LLM-free degraded mode

Card source: `docs/requirements/learned-intent-fallback.md` (not a `07` row) · owner **Dev A** (human, overrides the doc's "Dev B with Dev A") · branch `feat/learned-intent-fallback` (base `develop`) · spec date 2026-10-01.

Naming: the requirement doc's items are written **REQ-R1..REQ-R4**, and its open questions **REQ-Q1..REQ-Q7**. Bare **R1–R13** always means the safety rules in `06` §1. Pass-1 questions are **Q1–Q6**, and their answers are the human's.

## Objective

The team trains a small, local, CPU-only intent classifier: the first component the team trains itself (D4.6, D4.8–D4.10, K6). It also becomes the NLU of a **degraded mode** that keeps Cardy serving when the LLM fails or `LLM_DISABLED` is on (D5.2e, D6.3), where today every such turn hands off. The card delivers:

- 2,902 accepted AI-generated training utterances (838 rejected ones stay in the files). *Amended mid-card: the plan was 2,640; see D19 for the count and for what the human read.*
- An offline comparison of C0–C4 against Ref with a written model and threshold choice.
- A reproducible training command, and model artifacts pinned by sha256 that are never committed (a local, git-ignored bundle; S3 is deferred to the deploy).
- The degraded path in the served graph.
- An intent registry that the graph, the NLU prompt and the classifier are checked against.
- CI checks, a model card and a README section.

It serves the requirement doc's Done-when 1–6, the "End-to-end check of degraded mode", and the "Expected report (mock)" layout.

## Contracts (delta only)

### `ml/intent/data/<locale>/<class>.yaml`
```yaml
provenance: ai-generated-human-audited
version: 1                       # data version; the run record also stores the sha256 of all files
locale: es-ar                    # es-mx | es-co | es-ar | pt-br
class: card_block                # registry intent with classifier:true, or a scope.yaml topic
items:
  - text: "che, bloqueame la ⟨CARD_1⟩ ya"
    intents: [card_block]        # [] for a scope class
    status: clear                # clear | out_of_scope | out_of_market
    topic: null                  # set for scope classes
    family: card_block-es-ar-03
    slot: regional               # plain | regional | typo_informal | negation | hard_negative | short_answer | card_type (amended mid-card)
    origin: seed                 # seed | paraphrase   (both generated)
    generator: gpt-6-luna:intent_gen@v1   # @v1 | @v2 | @v3 (amended mid-card)
    accepted: true               # true | false | null (null = not audited yet)
```

### `backend/app/domains/conversation/intents.yaml` (registry)
```yaml
label_set_version: 1
intents:
  - {intent: card_block, node: card_block, tier: core, classifier: true,
     training_dir: ml/intent/data, lexicon_key: card_block}
  - {intent: travel_notice, node: null, tier: stretch, classifier: false,
     training_dir: null, lexicon_key: null}      # node null → unsupported
  # tier: core | management | stretch. One row per member of the Intent Literal (26).
```

### Classifier (inference)
```python
class IntentClassifier(Protocol):
    version: str            # "intent_clf@v4" (the pinned bundle; each export bumps it)
    label_set_version: int
    def predict(self, text: str, *, pending: Pending | None,
                country: str | None, previous_language: str) -> NLUResult: ...
```
`text` is the same masked `user_text` `understand` gets. Bundle `manifest.json`: `{model_id, candidate, hyperparameters, tau, labels, label_set_version, data_version, data_sha256, seed, embedding_model | null}`. `ml/intent/model.lock` (committed): `{version, sha256, label_set_version, s3_uri: null}`. `s3_uri` stays `null` until the deploy item (OQ4). Settings: `INTENT_MODEL_DIR` (the bundle's path inside the image, outside the dev bind mount).

### Graph state and policy
- `GraphState.degraded: NotRequired[bool]`: graph-local, not checkpointed, reset by `load_session` (`True` under `LLM_DISABLED`). Per turn: `True` only when the turn ran the degraded path (D5, amended mid-card).
- `policies/escalation.yaml`: `degraded_handoff_intents: [transaction_search, general_question, decline_explain]` (v6; `decline_explain` added mid-card, D7).
- New template `clarify_rephrase` (ES, PT) in `templates.py`.

### Audit (`04` §audit events)
- `reply_sent.payload.degraded: bool` (always present; `true` only on a turn that ran the degraded path). The same per-turn value goes to the OTel span attribute `cardy.degraded` and to the non-prod `debug` SSE event.
- `nlu_result.payload.source: "llm" | "classifier"`, and `classifier_version`, `label_set_version` when the source is the classifier.

### Make targets
`intent-gen` (fill cells up to 30 accepted, `LOCALE=`/`CLASS=` optional) · `intent-train` (`CANDIDATE=` optional, `SEED=42`) · `intent-compare` (writes the report run, the bundle in `ml/intent/models/` and `model.lock`) · `make check` runs `python -m ml.intent.check`. `make eval` gains `FAULTS=` (→ `--faults`, unioned with each case's `setup.faults`; criterion 8). `intent-publish` and the S3 `intent-fetch` are **not** part of this card (OQ4).

## Boundaries

- **Always:** fake LLM and stub classifier in tests; masked text into the classifier; `NLUResult` validation on classifier output; read `eval/scenarios/heldout/` read-only, and in `_staging/heldout/` edit only the five D23 cases; update `02`/`04`/`06`/`01`/`05` and the decision log in the same PR as the behavior change.
- **Ask first:** any new runtime dependency other than the D15 winner's; changing τ's cost rule; changing any `policies/*.yaml` beyond D7; editing any `_staging/heldout/` file beyond the five D23 cases; building any S3 leg (OQ4); a live LLM run beyond the Ref column and data generation.
- **Never:** commit a model artifact or embedding file; edit `eval/scenarios/heldout/` or `heldout.lock`; put training text from `eval/` into `ml/intent/data/`; edit `nlu@v4.md`; give the classifier or degraded path any tool, token or write the normal path lacks; let the backend call S3 or the network at startup; show a degraded-mode notice to the customer.

## Success criteria

1. `make intent-train SEED=42` run twice on the same data writes two run records with identical `metrics` and prediction hashes.
2. `ml/intent/runs/<run_id>/nlu_classifier.md` exists. 5. `make check` runs `ml.intent.check` and `test_registry_consistency`. Deliberately adding a dev text to training data, or taking a cell below 29 accepted items, makes `make check` fail. *Amended mid-card: "removing one accepted item fails" is superseded. 7.
